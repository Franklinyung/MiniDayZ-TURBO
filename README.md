# MiniDayZ 2.3.8 · TURBO

基于 **MiniDayZ+ Reimagined 2.3.8** 的单机爽玩改版，直接改 `data.js` 数据，不改引擎。

**四大改动：子弹用不完（越用越多）、经验 ×15、随机掉落 100% 出 PKM、堆叠上限解锁。**

原版数据完整保留为 `data.orig.js`，随时可回退。

---

## 改动明细

| 项目 | 效果 | 实现 | 数量 |
|---|---|---|---|
| **子弹无限** | 开枪/用物品时数量 **+1** 而不是 -1，越打越多 | 消耗动作 `[0,[5,[21,6,...,VAR],[0,1]]]` → `[0,-1]` | **1906 处**（5 个槽位变量） |
| **堆叠上限** | 所有可堆叠物品上限解锁到 31,415,926 | 把 `perk_cybb` 条件三元压缩成常量 | 208 处 |
| **经验** | 所有收益 ×15，死亡扣分不变 | 递归给经验表达式里每个常量 ×15 | 128 个常量 |
| **掉落** | 989 处随机掉落 100% 必出 PKM 或 7.62x54R | 末位 `-1` → `246`/`13` | 枪 329 / 弹 660 |

> ⚠️ **注意**：消耗动作是游戏里通用的「物品数量 -1」，所以不只子弹，**食物、药品、材料也都变成用不完**。这是改 `data.js` 层面最容易做到可靠的方式；如果你只想让子弹无限，需要按物品 ID 逐个分流，可以再改。
>
> 📌 **关键细节**：背包格对象(obj6) 不是只有一个数量变量，而是 **5 个**（`var11/12/13/15/16`，对应手 / 背包 / 胸挂 / 裤子 / 外衣等不同装备槽位）。弹药存在哪个变量里取决于你从哪个容器取用，所以**必须 5 个全改**，只改 var12 会出现「部分枪的子弹还在减少」——v3 初版就是这个 bug。

## 为什么选 PKM

从游戏内置描述文本提取的全部枪械属性：

| 武器 | 伤害 | 射速 | 弹匣 | 弹药 | 附加条件 |
|---|---|---|---|---|---|
| **PKM** (id 246) | **60-100** | 650 发/分 | 100 | 7.62x54R | 无 ✓ |
| M134 加特林 (id 245) | 60-100 | 1000 发/分 | 300 | .308 Win | 需电池，移速 -10% |
| 短管莫辛 (id 736) | 79-131 | 1.3 秒/发 | 5 | 7.62x54R | 栓动，射速慢 |
| M249 SAW (id 241) | 25-41 | 1000 发/分 | 200 | 5.56x45 | 伤害低 |

**PKM 是唯一"最高伤害档 + 大弹链 + 零负面"的枪。** 想换成加特林：`GUN_ID=245`、`AMMO_ID=138`。

## 调整与重新生成

编辑 `make_turbo.py` 顶部常量，然后：

```bash
python3 make_turbo.py
```

| 常量 | 当前值 | 含义 |
|---|---|---|
| `XP_MULT` | `15` | 经验倍率 |
| `GUN_ID` | `246` | 枪 ID（PKM） |
| `AMMO_ID` | `13` | 弹药 ID（7.62x54R） |
| `GUN_EVERY` | `3` | 每 N 次掉落 1 次是枪，其余弹药 |
| `INFINITE_ITEMS` | `True` | 物品消耗 -1 → +1 |
| `INFINITE_STACK` | `True` | 堆叠上限解锁 |

生成器**永远从 `data.orig.js` 读取**，反复重跑不会累积修改。启动时会校验枪/弹药 ID 是否存在于游戏的 `Spawn_drop` 生成表（345 个合法 ID），不存在直接中止。

## 实现原理

`data.js` 是 Construct 2 导出的明文 JSON，游戏逻辑是序列化的事件树。

**经验动作**
```json
[-1,122,null,UID,false,[[11,"expierence_points"],[7,[0,200]]]]
```
`[7,[0,N]]` 是加 N 点经验。原版混着简单数值和嵌套三元（按 perk 取不同值），所以**不做公式包装**，而是递归遍历表达式树，把每个 `[0,N]`（N>0）常量直接乘 15 —— 不依赖任何运算符节点语义，零歧义。负值（死亡扣分）跳过。

**掉落调用**
```json
[189,69,null,UID,false,[[1,[2,"Spawn_drop"]],[13,...,[7,[0,-1]]]]]
```
最后一个参数是物品 ID，`-1` = 随机。换成具体 ID 即固定掉落。

**物品消耗**
```json
[0,[5,[21,6,false,null,12],[0,1]]]
```
`[21,6,false,null,12]` = 背包格(obj6) 的实例变量 12（该格物品数量），`[5,a,b]` = 算术 a - b。把常量 `1` 改成 `-1`，就变成「数量 - (-1)」= 数量 +1。只精确匹配这个结构，不碰其它 454 处中的 72 处「读取」用法。

**堆叠上限**
```json
[18,[12,[23,"perk_cybb"],[0,1]],[0,31415926],[0,50]]
```
`[18,条件,真值,假值]` 是三元。`perk_cybb` 是"超编"perk，开启时上限 31415926。直接把整个三元压成 `[0,31415926]`，无需解锁 perk。

## 注意事项

- **单机专用**。`mdzac.js` 会给 `data.js` 算 hash 供联机时上报校验，本版 hash 与原版不同，**不要用它进联机服务器**。
- 存档在浏览器 localStorage / IndexedDB。TURBO 和原版部署在同一 origin 会共用存档。
- 只改了 `data.js`，`images/`、`media/`、语言包、引擎文件与原版完全一致。
