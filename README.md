# MiniDayZ 2.3.8 · TURBO

基于 **MiniDayZ+ Reimagined 2.3.8** 的单机爽玩改版，直接改 `data.js` 数据，不改引擎。

**改了什么：所有随机掉落 100% 变成「最强枪 PKM」或「它的弹药 7.62x54R」，经验收益 ×15。**

原版数据完整保留为 `data.orig.js`，随时可回退。

---

## 为什么选 PKM

从游戏内置的描述文本里提取了全部枪械属性对比：

| 武器 | 伤害 | 射速 | 弹匣 | 弹药 | 附加条件 |
|---|---|---|---|---|---|
| **PKM** (id 246) | **60-100** | 650 发/分 | 100 | 7.62x54R | 无 ✓ |
| M134 加特林 (id 245) | 60-100 | 1000 发/分 | 300 | .308 Win | **需要电池，移速 -10%** |
| 短管莫辛 (id 736) | 79-131 | 1.3 秒/发 | 5 | 7.62x54R | 栓动，射速极慢 |
| M249 SAW (id 241) | 25-41 | 1000 发/分 | 200 | 5.56x45 | 伤害低 |
| SVD (id 168) | 71-119 | 慢 | 10 | 7.62x54R | 半自动，弹匣小 |

**PKM 是唯一同时满足「最高伤害档位 + 大容量弹链 + 无负面条件」的武器**。加特林伤害相同但吃电池还减速，莫辛/ SVD 单发伤害高但射速拖后腿。

想换成加特林：把 `make_turbo.py` 里 `GUN_ID` 改成 `245`、`AMMO_ID` 改成 `138`，重跑即可。

## 当前改动明细

| 项目 | 改动 | 数量 |
|---|---|---|
| 经验 | 所有收益 × 15（200→3000、8→120、50→750…）；死亡/重置扣分保持原样 | 82 处数值 + 20 处复杂表达式 |
| 掉落 | 原本传 `-1`（随机物品）的调用，全部改为必出 PKM 或 7.62x54R | 989 处全部（100%）：枪 329 处 / 弹药 660 处 |

> 枪/弹比例由 `GUN_EVERY = 3` 控制：每 3 次掉落 1 次枪、2 次弹药。改成 `1` 就是一半一半，`10` 就是十分之一是枪。

## 调整与重新生成

编辑 `make_turbo.py` 顶部常量，然后：

```bash
python3 make_turbo.py
```

| 常量 | 当前值 | 含义 |
|---|---|---|
| `XP_MULT` | `15` | 经验倍率 |
| `GUN_ID` | `246` | 枪的物品 ID（PKM） |
| `AMMO_ID` | `13` | 弹药的物品 ID（7.62x54R） |
| `GUN_EVERY` | `3` | 每 N 次掉落出 1 次枪，其余出弹药 |

生成器**永远从 `data.orig.js` 读取**，所以反复重跑不会累积修改。

脚本启动时会自动校验 `GUN_ID` / `AMMO_ID` 是否存在于游戏的 `Spawn_drop` 生成表（345 个合法 ID），不存在会直接中止并报错，不会产出"空物品"。

## 还原

```bash
cp data.orig.js data.js     # TURBO 变回原版
```

## 运行

游戏不能通过 `file://` 打开，需要 HTTP 服务：

```bash
python3 -m http.server 8080
# 或仓库根目录的 serve.py
```

然后访问 `http://127.0.0.1:8080/`。进游戏按 `F11` 全屏，`ESC` 里把操作模式从摇杆改成 `tap/draw` 更适合鼠标。

## 实现原理

`data.js` 是 Construct 2 导出的明文 JSON，游戏逻辑是事件树的序列化。两个关键结构：

**经验动作**
```json
[-1,122,null,UID,false,[[11,"expierence_points"],[7,[0,200]]]]
```
`[7,[0,N]]` 是"加 N 点经验"。原版 82 处是这种简单数值，乘以倍率即可；另有 20 处是复杂表达式（如按难度系数算），用 C2 的乘法节点包一层：
```json
[7,[6,[0,15],原表达式]]
```
类型 `6` = 乘法。负值（死亡扣分）**不处理**，避免惩罚也翻倍。

**掉落调用**
```json
[189,69,null,UID,false,[[1,[2,"Spawn_drop"]],[13,...,[7,[0,-1]]]]]
```
最后一个参数是物品 ID，`-1` 表示随机。替换成具体 ID 就变成固定掉落。

改动的合法性由 `Spawn_drop` 函数体内的分派表保证：形如 `[[0,[0,0]],[8,0],[7,[0,246]]]` 的条目定义了每个可生成的 ID。

## 注意事项

- **单机专用**。`mdzac.js` 会给 `data.js` 算 hash 供联机时上报校验，本版 hash 与原版不同，**不要用它进联机服务器**。
- 存档在浏览器 localStorage / IndexedDB。TURBO 和原版若部署在同一 origin（同一端口）会共用存档，切换前留意。
- 只改了 `data.js`，`images/`、`media/`、语言包、引擎文件与原版完全一致（已做全树 diff 校验）。
