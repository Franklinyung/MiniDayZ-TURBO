# MiniDayZ 2.3.8 · TURBO

基于 **MiniDayZ+ Reimagined 2.3.8** 的单机爽玩改版，直接改 `data.js` 数据，不改引擎。

**核心：`Spawn_drop` 的第一个参数才是物品 ID —— 45% 的物资生成点直接出枪，37 把枪全覆盖，每把枪旁边必有它对应的 100 发弹药。**

原版数据完整保留为 `data.orig.js`，随时可回退。

## 调整

编辑 `make_turbo.py` 顶部常量后重跑：

```bash
python3 make_turbo.py
```

| 常量 | 当前值 | 含义 |
|---|---|---|
| `XP_MULT` | `15` | 经验倍率 |
| `LOOT_GUN_RATE` | `0.80` | 多少比例的物资点用于枪+弹药配对（`1.0` = 全部） |
| `ALL_AMMO_COUNT` | `100` | 所有弹药的固定数量 |
| `AMMO_308_ALL_RANDOM` | `True` | 剩余物资点是否全部改成 .308 |
| `AMMO_OBJECTS` | 17 项 | 各口径弹药对应的对象 ID 列表 |
| `INFINITE_ITEMS` | `True` | 物品消耗 -1 → +1 |
| `INFINITE_STACK` | `True` | 堆叠上限解锁 |
| `SPEED_BONUS` | `20` | 速度加成。总速度 = 5 + 此值。5倍=20，10倍=45 |
| `GUN_AMMO` | 37 组 | 枪 → 弹药映射，可自行增删 |

生成器**永远从 `data.orig.js` 读取**，反复重跑不会累积。启动时校验每把枪和它的弹药都在游戏的 `Spawn_drop` 生成表里（345 个合法 ID），有任何一个不存在就中止，不会产出空物品。

## 🚨 最重要：Service Worker 缓存（为什么之前改了都没效果）

游戏注册了 Service Worker 做离线缓存（`sw.js` + `offline.js`）。`sw.js` 用 `offline.js` 里的 **`version`** 字段生成缓存名：

```json
{ "version": "2.3.8-turbo-058e4a2028ea", "fileList": ["data.js", ...] }
```

**版本号不变 → 缓存名不变 → 浏览器直接用缓存里的旧 `data.js`，改文件毫无作用。**

这就是为什么前面十几轮改掉落、改弹药数量、改速度全部"没生效"——你玩的一直是第一次缓存的旧数据。

### 解决办法（生成器已自动处理）

`make_turbo.py` 每次生成后会**自动改写 `offline.js` 的 version**（用新 data.js 的 md5 前 12 位），强制 SW 建立新缓存并重新下载。

### 你本地如果还看到旧效果

SW 更新有两步，最保险的做法：

1. **F12 → Application → Storage → Clear site data**（或 Ctrl+Shift+Delete 勾选"Cookie 及其他站点数据"）
2. 或者开一个**无痕窗口**访问
3. 然后 **New Game** 开新档

验证是否用上了新数据：F12 Console 执行
```js
(await (await fetch('data.js')).text()).match(/2\.3\.8-turbo-[a-f0-9]+/)?.[0]
```
再查 `Application → Cache Storage`，缓存名应带 `turbo-` 前缀。

## ⚠️ v7 修正（Spawn_drop 参数含义）

`Spawn_drop` 的调用形式是：

```json
[13, [7,[0,350]], [7,[20,181,65,...]], [7,[5,...]], [7,[0,-1]]]
      └─ 参数1：物品ID    └─ x          └─ y        └─ 变体/耐久
```

- **参数 1 = 物品 ID**（350=T恤、300=牛仔裤、14=7.62x39弹药…）
- **参数 4 = 变体/耐久**，`-1` 表示默认

前几版错误地改了**参数 4**，所以物资点刷出来的还是原版物品，枪自然找不到。v7 改为修改**参数 1**，这才是真正决定生成什么物品的地方。

## 实现原理

`data.js` 是 Construct 2 导出的明文 JSON，游戏逻辑是序列化的事件树。

**掉落调用**
```json
[189,69,null,UID,false,[[1,[2,"Spawn_drop"]],[13,...,[7,[0,-1]]]]]
```
最后一个参数是物品 ID，`-1` = 随机物品。把前 790 个这样的 `-1` 按「偶数位放枪 / 奇数位放该枪弹药」交替替换，就形成成对掉落 —— 因为相邻两个调用属于同一次物资生成，所以**捡到枪的同一堆物资里必有它的子弹**。

**经验动作**
```json
[-1,122,null,UID,false,[[11,"expierence_points"],[7,[0,200]]]]
```
递归遍历表达式树，把每个 `[0,N]`（N>0）常量直接乘 15。不做运算符包装，不依赖任何运算符节点的语义。负值（死亡扣分）跳过。

**物品消耗**
```json
[0,[5,[21,6,false,null,VAR],[0,1]]]
```
`[21,6,false,null,VAR]` = 背包格(obj6) 的实例变量（`11/12/13/15/16` 五个装备槽位），`[5,a,b]` = `a - b`。把常量 `1` 改成 `-1`，变成「数量 - (-1)」= 数量 +1。只精确匹配这个结构，不碰另外 72 处「读取」用法。

**堆叠上限**
```json
[18,[12,[23,"perk_cybb"],[0,1]],[0,31415926],[0,50]]
```
三元表达式，`perk_cybb`（超编 perk）开启时上限 31415926。把整个三元压成常量即可。

## 注意事项

- **单机专用**。`mdzac.js` 会给 `data.js` 算 hash 供联机时上报校验，本版 hash 与原版不同，**不要进联机服务器**。
- 存档在浏览器 localStorage / IndexedDB，与相同 origin 的原版共用。
- 只改了 `data.js`，`images/`、`media/`、语言包、引擎文件与原版完全一致。
- **弹匣内子弹（枪上的数字）仍会正常减少** —— 那是武器实例的运行时状态，`data.js` 的事件树里没有对应的写入点，改不动。但物资点大量出枪出弹、且背包弹药消耗变 +1，实际不会缺子弹。
